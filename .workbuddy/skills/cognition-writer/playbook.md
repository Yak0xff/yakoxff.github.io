# 写法手册

这套规范来自用户多次明确的反馈，针对两个**互相独立**的毛病。别把它们混成一件事。

## 一、说教感：病根是「结论前置」

先说道理、再找例子证明，等于替读者思考。读者要的是自己从画面里看出来。

**画面驱动**：

- 具体名词密度要高：人名、地名、物件、动作、数字、色值、文件名、像素、时间戳。抽象名词一多就是空转——重点盯这几个：`流程`、`机制`、`价值`、`通道`、`形态`、`维度`、`体系`、`路径`、`赋能`、`闭环`、`底层逻辑`、`方法论`。
- 判断句放段尾，**只一句**，后面不再补解释。写完这句就换段或换话题。
- 金句要能「画出来」：
  - 好：`把梯子从墙上卸了，顺手把爬梯子这门手艺一起贬值了`
  - 好：`别光盯着灯。去看看墙里的线。`
  - 坏：`定价权从来不在干活的人手里`（格言，没有画面）
- 引导词用多了就是老师腔：`你想想`、`说到底`、`反过来讲`、`其实`、`本质上`、`值得注意的是`、`不难发现`。`你发现没有` 全篇最多一次，最好零次。
- 不用「首先 / 其次 / 最后」搭骨架，不写「综上所述」。

## 二、节奏问题：病根是「不给他时间自己想」

信息密度够、读感不对，是因为开篇甩新名词，然后一路狂奔，全程「我全想好了你跟着我跑」。要的是「我边想边跟你说」。

- **慢起点**：开篇 200 字内不出现新名词。先给一个读者自己经历过的瞬间——两张并排的截图、一杯早上倒的凉水、光标在空白文档里闪、在触控板上来回滑了七八次。让他先想起来，再轻轻一推。
- **每层一停顿**：讲完一层加一句短的、物件化的停顿句，确认读者跟上再往下。
  - `那杯水就是这时候接的。`
  - `尺子还搁在键盘右边，只是上面多贴了几道胶带。`
  - `你品品这个顺序。`
  - 停顿句用画面，不用口头禅堆。
- **主线类比贯穿 ≥3 次**：动笔前先定一个能承载全篇的具体物件，标题、中段、底层逻辑、结尾各回扣一次。
  - 已用过的：`付印前的校样 / 红笔`（设计编年）、`一枚点如何量出整套坐标`（品牌命名）。
  - 辅助比喻每段换一个，不重复。
- **结尾留画面，不总结**：停在一个物件或动作上。
  - 好：`它还没被任何人分享过。`
  - 好：`光标还在闪。`
  - 坏：`说到底，克制才是这套设计的底层逻辑。`

## 三、结构与事实

- 不套固定模板。常见骨架：具体瞬间 → 一层事实 → 停顿 → 第二层 → 停顿 → 底层规则（可列表/表格）→ 编年或清单 → 画面结尾。
- 底层规则要能落地：给变量、数值、代码、文件路径，不写「要重视一致性」这种话。
- 资料里的数字带单位和口径（如 `47.5KB / gzip 16.0KB`、`1440 视口下 762px 容器`）。
- 同一个概念全篇一个名字。别在 `品牌点 / 朱砂圆 / 原子 / 标记` 之间来回换。
- 可以做一张编年表或对照表收口，但表格后面不要再补一段总结。

## 四、自检清单（对应 lint.py）

| 项 | 标准 |
|---|---|
| 开篇 200 字 | 抽象名词命中数 0，且没有抛专有术语 |
| 具体名词密度 | 越高越好；数字、专名、物件、单位都算 |
| 抽象名词 | 命中即人工复核，看能否换成具体物件 |
| 引导词 | 合计越少越好；`你发现没有` ≤ 1 |
| 判断句位置 | 段落最后一句；后面不接解释 |
| 主线类比 | `--motif` 指定词出现 ≥ 3 次 |
| 结尾 | 不出现总结词，停在画面上 |
| 事实 | 人名 / 数字 / 出处与资料逐条对齐 |

脚本只报数量，不判好坏。WARN 不等于必须改——为了过检查把句子写拧，比 WARN 更糟。

主线若是复合意象（如 `付印前的校样 / 红笔`），`--motif` 选最具象的那个词，必要时分别跑两次；只统计一个词会低估贯穿次数。回归样本：`一笔，一枚点` 用 `--motif 一点` 得 0 WARN；`付印之前` 用 `--motif 校样` 报 2 项（`其实` 3 次、主线词命中 2 次），属真实提示。

## 五、已发表的同规范样本

- `content/posts/付印之前：三十九道红笔.md`：主线「校样 / 红笔」，慢起点（两张截图 + 凉水），四层底层规则，13 行编年表，结尾停在分享卡上。
- `content/posts/一笔，一枚点：为什么最后叫「一点」.md`：主线「从一点量出去」，命名史用真实记录，四重身份 + 四层规则，结尾停在光标。

写之前读一篇找手感，比读规范本身更快。
