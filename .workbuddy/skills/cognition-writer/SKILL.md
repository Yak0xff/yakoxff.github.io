# 认知类长文写作（纯按需）

本站「一点」的文风要求已经踩过坑、定过型，全部写在 `playbook.md`。**每次动笔前先读它**，不要凭通用写作直觉写。

## 何时用

- 用户给一批资料（本地文件、链接、PDF、截图、微信文章、随手记的片段），要求写认知类 / 设计复盘 / 思考类长文。
- 用户说「按本站文风写」「不要 AI 腔」「按 cognition-writer 写」。
- 不适用：育儿号（人设「林知远」是另一套文风）、公众号排版、摘要改写、长图/卡片出图。

## 工作流

1. **读资料，先对齐事实**。人名、地名、物件、数字、出处逐条记下。资料里没有的不写，不替用户编经历或补数据。
2. **定题眼，先列选项**。题眼属于重大方向，给 2–4 个方向让用户选，不要自己拍板。主线类比也在这里定下来（全篇要出现 ≥3 次）。
3. **成稿**。按 `playbook.md`：慢起点（200 字内不抛新名词）、画面驱动、每层一停顿、判断句压段尾、结尾留画面不总结。
4. **跑自检**：
   ```bash
   python3 .workbuddy/skills/cognition-writer/scripts/lint.py <草稿.md> --motif "<主线类比词>"
   ```
   按报告修一遍，尤其看 WARN 项。脚本只做可量化的部分，挡不住观点是否真新——后者要自己判断。
5. **只进草稿区**。默认写到 `content/posts/`，front matter 带 `draft: true`；**不 git commit、不 push、不发布**。把成品和自检结果交给用户过目。

## 硬规则

- **不凑数**：资料不足、题眼没想清楚，就直说「这次不写」，不产出占位稿。
- **不自动发布**：草稿制不可省。用户没明确说「发」之前，不许提交推送。
- **不建定时任务**：本 skill 是纯按需模式，不创建自动化、不定时扫描。
- **不牺牲人读体验换机器指标**：lint 的 WARN 是提示，不是硬指标；为了过检查把句子写坏，比 WARN 更糟。
- 术语一致：一个概念一个名字；具体数字带单位和口径。

## 落点

| 文件 | 作用 |
