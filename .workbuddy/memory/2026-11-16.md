## 写作规范落地：项目级 skill `cognition-writer`（纯按需，不建自动化）

- 用户问「提供资料能否不断、不定时输出高质量认知类文章」，给了四种落地方式，用户选 **「纯按需，不建自动化」**：不引入定时任务，每次丢资料 + 一句话即时成稿，但先把写作规范落成文件保证文风稳定。
- **现状核查**：写作偏好在长期记忆里完整（慢起点/画面驱动/娓娓道来/主线类比≥3/判断句压段尾/结尾留画面/引导词克制），但本机 `~/.workbuddy/skills/` 无 `jiubian-style-writer`，只有 `article-*` 通用技能；项目级 `.workbuddy/skills/` 此前不存在。所以规范只存在于上下文，定时任务跑起来会漂回 AI 腔。
- **落地三件套**（只显式 add 这三个文件，`git add .workbuddy/` 会把大量历史截图带进来）：
  - `.workbuddy/skills/cognition-writer/SKILL.md`：触发条件（认知/思考/复盘类，排除育儿号与出图）、5 步工作流（对齐事实 → 题眼列选项 → 成稿 → lint → 只进草稿）、硬规则（不凑数、不自动发布、不建定时任务、不牺牲人读体验过检查）。
  - `playbook.md`：说教感（结论前置）与节奏（不给时间想）是两个独立毛病；正反金句、慢起点 200 字、层间停顿句、结尾留画面、术语与事实纪律、自检清单、两篇已发表样本。
  - `scripts/lint.py`：无依赖量化自检，支持 `--motif` / `--json` / `--strict`；检查开篇 200 字抽象名词、引导词、「你发现没有」≤1、结尾总结词、主线类比≥3、具体名词密度、段尾判断句、篇幅。
- **回归验证**：`付印之前：三十九道红笔.md --motif 校样` → 2 WARN（`其实`×3、主线词命中 2 次）；`一笔，一枚点… --motif 一点` → 0 WARN。均在开篇抽象名词 0、结尾无总结词上通过。说明脚本能检出真实信号，不是空转。复合意象需在 playbook 里注明 `--motif` 选最具象词。
- **草稿制**：默认写 `content/posts/` 且 `draft: true`，不 commit / 不 push / 不发布，交用户过目。
